RAG Pipeline

A RAG pipeline that doesn't trust its first draft

Most retrieval chatbots answer confidently from whatever they retrieved. This one asks itself four questions before an answer reaches the user, and loops until the answer is supported and useful.

The problem

A retrieval-augmented model will happily answer from irrelevant chunks, or blend retrieved facts with invented ones. Users can't tell which sentences are grounded.

Approach

The pipeline follows the reflection idea from Self-RAG (Asai et al., 2023), implemented with prompted judges in a LangGraph state machine rather than a fine-tuned model.

First it decides whether the question needs the documents at all; general questions skip retrieval. Retrieved chunks pass a relevance filter, and if nothing survives the bot says it found no answer instead of guessing.

The draft answer is graded for support: is every claim backed by the chunks? If not, it is rewritten as direct quotes and checked again. Finally it is graded for usefulness; an answer that doesn't address the question triggers a rewritten search query and a fresh retrieval.

Outcome

Users can upload their own PDFs, Word files, text or Markdown and ask questions, with sample documents bundled for a first try. Each node is a plain function, so every judgement is unit-testable on its own.
