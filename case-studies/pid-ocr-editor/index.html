OCR Editor for Engineering Drawings

Reading engineering drawings, one tag at a time

P&ID sheets pack hundreds of tiny, rotated labels between pipes and symbols. At Flagestrator, an early-stage startup, I architected and built the OCR pipeline that finds them, reads them, and hands every box to a person to correct.

Role
AI Engineer — architected and built the pipeline, editor and export
Status
Live on Hugging Face
Stack
PaddleOCR PP-OCRv5, PaddleOCR-VL, Gradio

The problem

Piping and instrumentation diagrams are the opposite of a clean document. Equipment tags like P-101 or FV-12 sit inside circles, line numbers run vertically along pipes, and annotations crowd into whatever whitespace is left. Generic OCR either misses them or reads the drawing's linework as text.

The people who use these sheets don't need a perfect model. They need every tag found, a fast way to fix the few that are wrong, and an output they can hand on.

Approach

Classic PaddleOCR (PP-OCRv5 detection and recognition) runs on CPU and produces the boxes. PaddleOCR-VL then re-reads exactly those boxes on a GPU, so the two engines can be compared line for line instead of layout against layout. Both outputs are normalised to the same {text, box} shape.

The editor overlays an invisible, clickable box on every detected line. Gradio has no such component, so it is custom HTML and a script injected into the page; saved edits sync back to the server as JSON.

Export redacts each edited box — filling it with colour sampled from the surrounding background — and re-inserts the corrected text, fitted to the original box, into a new PDF.

Outcome

Every tag on the sheet comes back as a box a person can check. Where the two engines read a line differently, that line is worth a human look — the side-by-side view puts it in front of the reviewer, they fix it in one click, and the corrected drawing exports as a clean PDF.
